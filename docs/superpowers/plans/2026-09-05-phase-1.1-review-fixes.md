## Round 3 (response to a second independent review, still `FIX REQUIRED, DO NOT MERGE`)

1. **Agent Skills frontmatter spec compliance fixed** — verified against
   the actual cross-vendor spec (agentskills.io/specification, checked
   2026-09-05): `compatibility` must be a 1-500 char STRING (not an
   object), and `metadata` must be a flat string-to-string map (no nested
   objects/arrays/numbers). The Phase 1.1 round-1 validator got this
   backwards (treated `compatibility` as an object and accepted nested
   `metadata`). Fixed with RED tests first: string-compatibility PASS,
   object-compatibility FAIL, empty/over-500-char-compatibility FAIL,
   flat-string metadata PASS, nested-object/numeric metadata value FAIL.
   `registry/compatibility.json` (a separate, Hub-owned file, not SKILL.md
   frontmatter) is unaffected and remains structured.
2. **Bundles made binary-safe** — a regression test against a real
   temporary filesystem proved `collectSkillFiles`'s `fs.readFileSync(abs,
   'utf8')` corrupted non-UTF-8 bytes (e.g. a PNG asset). Fixed by reading
   raw `Buffer`s; added `readZip()` to `scripts/zip-writer.mjs` (a minimal
   STORE-only reader matching `buildZip`'s own output) so the round-trip
   can be unit-tested without depending on an external `unzip` binary.
   Both a synthetic invalid-UTF-8 byte sequence and ordinary UTF-8 text
   verified to round-trip byte-for-byte.
3. **GitHub Actions Node 20 warning actually eliminated, not just
   pinned-and-hoped** — checked the real CI log from the prior round and
   confirmed GitHub's own warning: `actions/checkout@v4` and
   `actions/setup-node@v4` both declare `runs.using: node20` in their
   `action.yml` (checked directly via `gh api .../contents/action.yml`).
   Their current major releases, v7.0.1 and v7.0.0 respectively, declare
   `node24` (also checked directly, not assumed). Re-pinned to those two
   releases' real commit SHAs.
4. **ChatGPT/Work documentation corrected** — the prior round's wording
   ("Personal Skills", "Plugin Directory upload") came from secondary/
   aggregator sources and did not hold up against the primary source.
   Re-verified directly against `learn.chatgpt.com/docs/build-skills`,
   which states, in its own words: "Standalone skills are available in the
   ChatGPT desktop app, Codex CLI, and IDE extension" and "Skills bundled
   in plugins are also available in Chat and Work across ChatGPT on the
   web, desktop, and mobile." `adapters/chatgpt/README.md` now uses only
   this confirmed terminology and states plainly that plugin-bundled
   packaging is NOT IMPLEMENTED (not silently assumed done), while the
   OpenAI API project-Skills bundle remains IMPLEMENTED.
5. All Phase 1 / Phase 1.1 round-1/round-2 fixes preserved — no regression
   to the L3/L4 gates, required-input/tool/capability/permission checks,
   project scope, real project-policy fixtures, full-render drift
   detection, installer ownership marker, real Claude Code/Codex installs,
   public-path sanitization, deterministic bundles, or the single
   `npm run verify` gate.
